# llm-rig

Локальный запуск большой LLM (Qwen3.8-27B uncensored) с контекстом 256k на арендованной
RTX 5090 (32 GB), все в оперативной памяти, плюс маленький поисковый прокси без зависимостей,
который роутит веб-поиск в Tavily или Exa с подсчетом остатка кредитов по каждому.

Все слушает только 127.0.0.1. Наружу ничего не открыто. На сервер заходишь по SSH-туннелю.

## Что внутри

- `llama` - llama.cpp `llama-server`, собранный под Blackwell (sm_120), OpenAI-совместимый
  API на `127.0.0.1:8080/v1`
- `proxy` - Node-прокси без зависимостей на `127.0.0.1:8000` для веб-поиска (Tavily / Exa)
  с переключением провайдера и просмотром остатка
- модель и все runtime-данные лежат в tmpfs (`/mnt/ram`), стираются при зачистке

## Требования (на арендованном боксе)

- NVIDIA RTX 5090 (32 GB), свежий драйвер
- желательно ~64 GB RAM (модель + KV-кеш в tmpfs, 32 GB RAM впритык)
- Docker + NVIDIA Container Toolkit (`setup.sh` поставит их сам, если нет)

## Быстрый старт

1. Скопируй конфиг и заполни ключи
```
cp .env.example .env
```
В `.env` четыре значения -

- `TAVILY_API_KEY`, `EXA_API_KEY` - ключи от этих двух сервисов (бесплатные тарифы, без карты)
- `LLM_API_KEY`, `PROXY_API_KEY` - пароли, которые ты сам придумываешь, они закрывают
  эндпоинты модели и поиска. Сгенерируй два через `openssl rand -hex 16`, вставь сюда и
  отдай тем, кто будет пользоваться

2. Запусти установку
```
./scripts/setup.sh
```
Смонтирует tmpfs, скачает модель, соберет и поднимет контейнеры.

3. С ноутбука открой SSH-туннель
```
ssh -L 8080:127.0.0.1:8080 -L 8000:127.0.0.1:8000 root@<server-ip>
```
4. Пользуйся эндпоинтами ниже.

## SSH-туннель, зачем

Сервисы слушают только 127.0.0.1, поэтому наружу ничего не открыто. Туннель - это способ
добраться до них с ноутбука через единственный открытый порт (SSH, порт 22).

`ssh -L 8080:127.0.0.1:8080` значит - "то, что приходит на порт 8080 моего ноутбука, пробрось
по SSH на порт 8080 localhost сервера". То есть `http://127.0.0.1:8080` на ноутбуке это на
самом деле `127.0.0.1:8080` на сервере.

Формат такой - `-L <порт-на-ноуте>:<адрес-на-сервере>:<порт-на-сервере>`, а так как сервисы
забинжены на localhost сервера, адрес-на-сервере всегда `127.0.0.1`.

## Эндпоинты

- LLM - `http://127.0.0.1:8080/v1` (OpenAI-совместимый, заголовок `Authorization: Bearer $LLM_API_KEY`)
- Поиск - `http://127.0.0.1:8000` (заголовок `Authorization: Bearer $PROXY_API_KEY`)

## Поисковый прокси

- `POST /search` с `{"query": "...", "provider": "tavily|exa"}` - provider необязателен,
  по умолчанию `SEARCH_PROVIDER`
- `GET /usage` отдает остаток кредитов по обоим провайдерам (Tavily через его `/usage`,
  Exa через локальный счетчик трат)
- переключение провайдера на запрос через `?provider=exa` или поле `provider` в теле

## Модель

Дефолтная модель - `ThinkingCap-Qwen3.8-27B-Uncensored-Heretic` (IQ4_XS GGUF), она сохраняет
thinking-режим Qwen3.8, а Heretic-аблейшн снимает отказы. Думает по умолчанию.

Влезает в 32 GB с контекстом 256k - ~15 GB веса + ~8.6 GB KV-кеш (q8_0) + активации. KV-кеш
в q8_0, потому что F16 KV не влезает в 32 GB на 256k, а BF16 KV на этой ветке нестабилен на
длинном контексте.

Альтернатива на Apache-2.0 - смени `MODEL_REPO` в `.env` на
`mlasli/Qwen3.8-27B-Heretic-Uncensored-IQ4_XS-GGUF`. У нее uncensored работает только при
thinking OFF (у ThinkingCap thinking остается).

Для квантов без сохраненного thinking переключай его в запросе через
`chat_template_kwargs: {"enable_thinking": true}` или `reasoning_effort` в OpenAI-совместимом API.

Лицензия - ThinkingCap это PolyForm Small Business, не Apache-2.0. Для личного использования
ок. Альтернатива mlasli на Apache-2.0.

## Друзья (мультиюзер)

Каждому другу нужен свой SSH-доступ на бокс, чтобы пользоваться туннелем. Два варианта -

- Добавь публичный ключ каждого друга в `~/.ssh/authorized_keys` на боксе, и они запускают ту
  же команду `ssh -L ...` со своего ноутбука. Приватно, наружу ничего не открыто. Рекомендую.
- Либо забинди сервисы на `0.0.0.0` вместо `127.0.0.1` в `docker-compose.yml`, тогда друзья
  ходят по `http://<server-ip>:8080` напрямую. Проще, но порты становятся публичными и их
  найдут сканеры, защита только API-ключами. Не рекомендую.

В обоих случаях друзья используют те же `LLM_API_KEY` / `PROXY_API_KEY` из `.env`.

## Приватность

- модель, логи и состояние прокси лежат в tmpfs на `/mnt/ram`, при зачистке размонтируются,
  на диске ничего не остается
- это защищает от данных, оставшихся на хосте после остановки, но не от живого злонамеренного
  хоста, который читает RAM/VRAM в процессе

## Безопасность

- все сервисы слушают только 127.0.0.1, публичных портов нет
- доступ только через SSH-туннель
- оба эндпоинта требуют API-ключ, даже на localhost
- контейнеры работают под non-root
- SSH держи только по ключу, без пароля

## Остановка

Три уровня, от легкого к полному -

- `docker compose stop` / `docker compose start` - пауза и запуск контейнеров. Модель остается
  в tmpfs, рестарт быстрый. За бокс при этом все равно платишь.
- `./scripts/teardown.sh` - стоп и удаление контейнеров + образов, размонтирование tmpfs,
  удаление `.env`. Чисто, но бокс еще арендован.
- Останови аренду на clore.ai - вот это реально останавливает поминутную оплату. Бокс и все
  на нем исчезает.

## Заметка про сборку

Сборка llama.cpp под CUDA (ядра Blackwell) занимает ~10-15 минут при первом запуске. Чтобы не
пересобирать на каждой аренде, запушь образ один раз в реестр (GHCR) и укажи `image:` вместо
сборки.
