# llm-rig

Локальный запуск большой LLM (Qwen3.8-27B uncensored) с контекстом 256k на арендованной
RTX 5090 (32 GB). Все в оперативной памяти. Есть поисковый прокси с кнопкой вкл/выкл и
подсчетом остатка по Tavily и Exa.

Все сервисы слушают только 127.0.0.1, наружу ничего не открыто, заходишь по SSH-туннелю.

Два способа запуска -

- `ghcr.io/promotezor/llm-rig:latest` - готовый образ, в clore вставил имя и все (основной путь)
- `scripts/setup-nodocker.sh` - ручной монтаж внутри контейнера clore, если образ не подошел
- `scripts/setup.sh` - docker-путь, для полного сервера (bare metal) с docker и tmpfs

Документы рядом -

- [CLORE.ru.md](CLORE.ru.md) - выбор сервера, темплейт заказа, доступ друзей, остановка
- [SECURITY.ru.md](SECURITY.ru.md) - приватность, анонимность, безопасность, модель угроз

## Образ для clore - вставил имя и готово

Образ собирается в GitHub Actions при пуше в main и лежит в GHCR. Внутри готовое: llama.cpp
под CUDA 12.8 (sm_120), поисковый прокси и стартовый скрипт, который сам качает модель и
поднимает сервер.

1. В clore при аренде выбери **Custom Docker image** и вставь
```
ghcr.io/promotezor/llm-rig:latest
```
2. В Environment variables добавь `LLM_API_KEY` со своим паролем (иначе сгенерируется
   случайный и будет виден в логах). Опционально `TAVILY_API_KEY`, `EXA_API_KEY`, `CTX`.
3. В **SSH Authorization** оставь оба поля пустыми. Это важно: включенная SSH-авторизация
   заставляет clore подменить entrypoint образа, и приложение не запустится
   (разбор в [CLORE.ru.md](CLORE.ru.md)). Если SSH все-таки нужен, добавь в **Startup script**
   строку `/app/launch.sh`
4. В Port forwarding добавь **8080 TCP** (для чата и страницы прогресса) и при желании
   **8000 TCP** (панель поиска).
5. Запускай и открой публичный адрес: сначала покажется страница прогресса с процентом
   скачивания модели, потом по тому же адресу откроется чат.

Адрес для входа clore выдаст в My Orders (вида `n1.de.clorecloud.net:порт`). Открываешь в
браузере `http://<этот-адрес>/`, вставляешь ключ и общаешься.

Внутри контейнер сам определяет машину, под каждую аренду править ничего не нужно -

- **видеокарта** - берет имя, количество и объем VRAM через nvidia-smi
- **квант модели** - по VRAM: 29GB+ и 21GB+ это IQ4_XS, 15GB+ это Q3_K_M, 11GB+ это Q2_K
- **размер контекста** - считает от свободной VRAM после весов и служебных буферов,
  от 8192 до 262144 токенов, в лог пишет что выбрал
- **где хранить модель** - перебирает `/dev/shm`, `/tmp`, `$HOME`, `/`, берет первое место
  с достаточным запасом, то есть RAM-диск если он есть, иначе обычный диск
- **прокси поиска** - поднимает только если заданы `TAVILY_API_KEY` или `EXA_API_KEY`

То есть на боксе с 256GB и RAM-диском модель ляжет в память, на обычном боксе в диск - и
в обоих случаях без правки конфигов. Логика выбора покрыта тестом `tests/detect-smoke.sh`
(на фейковых nvidia-smi, прогоняется без GPU).

Перед первым использованием один раз: пакет в GHCR по умолчанию приватный, сделай его
публичным (GitHub, профиль, Packages, llm-rig, Package settings, Change visibility, Public).
Иначе clore не сможет его скачать без своих registry-логинов.

## Часть 1 - первый запуск на новом сервере (один раз)

Свежеарендованный бокс, на нем ничего нет. Все команды выполняются на самом сервере.

1. Подключись к серверу по SSH. Адрес и доступ к SSH выдает clore при аренде
```
ssh root@<ip-сервера>
```

2. Скачай репозиторий. Он публичный, ключи не нужны
```
git clone https://github.com/promotezor/llm-rig.git
cd llm-rig
```

3. Создай конфиг и впиши 4 ключа
```
cp .env.example .env
nano .env
```
В `.env` четыре значения -

- `TAVILY_API_KEY` и `EXA_API_KEY` - ключи от этих двух сервисов, получаешь в их кабинетах
- `LLM_API_KEY` и `PROXY_API_KEY` - два пароля, которые придумываешь сам. Сгенерируй два через
  `openssl rand -hex 16` и вставь. Их же потом отдашь друзьям

4. Запусти установку
```
./scripts/setup.sh
```
Скрипт сам поставит docker и nvidia-toolkit, если их нет, смонтирует tmpfs, скачает модель,
соберет и поднимет контейнеры. Первый раз долго (~10-15 минут), потому что компилируется
llama.cpp под видеокарту.

Готово. Модель запущена и ждет подключений. Часть 1 повторяешь только при аренде нового бокса.

## Часть 2 - подключение, когда сервер уже работает (каждый раз)

Это делаешь и ты, и друзья. Тут одна команда, дальше все в браузере.

1. Открой туннель с ноутбука (держи это окно открытым, пока пользуешься)
```
ssh -L 8080:127.0.0.1:8080 -L 8000:127.0.0.1:8000 root@<ip-сервера>
```
Что это делает - сервисы закрыты от интернета, а эта команда пробрасывает их порты на твой
ноут. После нее `localhost:8080` и `localhost:8000` на твоем ноуте работают как будто ты на сервере.

2. Открой панель управления в браузере
```
http://127.0.0.1:8000
```
Вставь `PROXY_API_KEY` один раз. Увидишь остаток по Tavily и Exa и кнопку включить/выключить поиск.

3. Подключи свой чат-клиент к модели
- адрес `http://127.0.0.1:8080/v1`
- API-ключ - твой `LLM_API_KEY`

## Как выключить или включить поиск во время сессии

Открой панель `http://127.0.0.1:8000` и нажми кнопку "переключить". Состояние хранится в tmpfs,
переживает перезапуск прокси, сбрасывается вместе с арендой. Когда поиск выключен, `/search`
отвечает 403, и ни один запрос не уходит в Tavily/Exa.

## Поисковый прокси (для тех, кто дергает API напрямую)

- `POST /search` с `{"query": "...", "provider": "tavily|exa"}` - provider необязателен,
  по умолчанию `SEARCH_PROVIDER`
- `GET /usage` - остаток кредитов по обоим провайдерам плюс состояние поиска
- `POST /toggle` с `{"search": true|false}` - включить или выключить поиск
- переключение провайдера на запрос через `?provider=exa` или поле `provider`
- `SEARCH_DAILY_CAP` в `.env` - жесткий дневной лимит запросов, 0 значит без лимита

## Модель

Дефолтная модель - `ThinkingCap-Qwen3.8-27B-Uncensored-Heretic` (IQ4_XS GGUF), она сохраняет
thinking-режим Qwen3.8, а Heretic-аблейшн снимает отказы. Думает по умолчанию.

Влезает в 32 GB с контекстом 256k - ~15 GB веса + ~8.6 GB KV-кеш (q8_0) + активации. KV-кеш
в q8_0, потому что F16 KV не влезает в 32 GB на 256k, а BF16 KV на этой ветке нестабилен на
длинном контексте.

Альтернатива на Apache-2.0 - смени `MODEL_REPO` в `.env` на
`mlasli/Qwen3.8-27B-Heretic-Uncensored-IQ4_XS-GGUF`. У нее uncensored работает только при
thinking OFF (у ThinkingCap thinking остается).

Для квантов без сохраненного thinking переключай его в запросе через
`chat_template_kwargs: {"enable_thinking": true}` или `reasoning_effort` в OpenAI-совместимом API.

Лицензия - ThinkingCap это PolyForm Small Business, не Apache-2.0. Для личного использования
ок. Альтернатива mlasli на Apache-2.0.

## Друзья (мультиюзер)

Каждому другу нужен свой SSH-доступ на бокс, чтобы открыть туннель из Части 2. Варианты -

- Добавь публичный ключ друга в `~/.ssh/authorized_keys` на боксе, и он запускает ту же команду
  `ssh -L ...` со своего ноутбука. Приватно, наружу ничего не открыто. Рекомендую.
- Либо забинди сервисы на `0.0.0.0` вместо `127.0.0.1` в `docker-compose.yml`, тогда друзья ходят
  по `http://<ip-сервера>:8080` напрямую. Проще, но порты становятся публичными и их найдут
  сканеры, защита только API-ключами. Не рекомендую.

В обоих случаях друзья используют те же `LLM_API_KEY` и `PROXY_API_KEY` из `.env`.

Что именно отправить другу. Вариант через порт, ничего ставить не нужно

```
Ссылка: http://<адрес-из-my-orders>/
Ключ: <LLM_API_KEY>
Открой ссылку, введи ключ в поле и пиши в чат.
```

Вариант через туннель, нужен терминал и его ключ на машине

```
Выполни в терминале и не закрывай окно:
ssh -i ~/.ssh/id_ed25519_clore -L 8080:127.0.0.1:8080 -p <порт> root@<адрес>

Потом открой http://127.0.0.1:8080/ и введи ключ: <LLM_API_KEY>
```

Пусть открывает в инкогнито, тогда после закрытия окна диалог не остается ни в истории,
ни в хранилище браузера.

## Приватность

- модель, логи и состояние прокси лежат в tmpfs на `/mnt/ram`, при зачистке размонтируются,
  на диске ничего не остается
- это защищает от данных, оставшихся на хосте после остановки, но не от живого злонамеренного
  хоста, который читает RAM/VRAM в процессе

## Безопасность

- все сервисы слушают только 127.0.0.1, публичных портов нет
- доступ только через SSH-туннель
- оба эндпоинта требуют API-ключ, даже на localhost
- контейнеры работают под non-root
- SSH держи только по ключу, без пароля

## Остановка

Три уровня, от легкого к полному -

- `docker compose stop` / `docker compose start` - пауза и запуск контейнеров. Модель остается
  в tmpfs, рестарт быстрый. За бокс при этом все равно платишь.
- `./scripts/teardown.sh` - стоп и удаление контейнеров + образов, размонтирование tmpfs,
  удаление `.env`. Чисто, но бокс еще арендован.
- Останови аренду на clore.ai - вот это реально останавливает поминутную оплату. Бокс и все
  на нем исчезает.

## Заметка про сборку

Сборка llama.cpp под CUDA (ядра Blackwell) занимает ~10-15 минут при первом запуске. Чтобы не
пересобирать на каждой аренде, запушь образ один раз в реестр (GHCR) и укажи `image:` вместо
сборки.
